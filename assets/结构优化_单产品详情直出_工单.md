# 工单：单产品「两段 URL」按产品详情直出（Product + FAQPage 富摘要），URL 不变

## 目标 / 背景
阀门/焊枪是三段路由（category→subCategory→thirdCategory），产品详情与 Product/FAQPage JSON-LD 都在 `currentThirdCategory && !isOverview` 时直出静态 HTML，Google 能抓到问答富摘要。
但下面三类是**两段建模**：产品直接挂在 subCategory 上、没有 thirdCategoryId，URL 只有两段（category/sub），当前被渲染成「产品列表页」，**静态 HTML 不产出任何产品级 Product / FAQPage JSON-LD**，SEO 抓不到问答。

已核对：下列 **11 个 subCategory 每个都恰好只挂 1 个已发布产品**（sitemap 中正好是这 11 个两段 URL），不存在一子类多产品的歧义：
- copper-tubes：pancake-coils(ct-3)、mini-jumbo-coils(ct-mjc-1)、jumbo-coils(ct-1)、straight-tubes(ct-4)
- insulation-tubes：standard-b1-rubber-foam-insulation(im-1)、high-density-b1-rubber-foam-insulation(im-2)
- filter-driers：bidirectional-sae-flare(fd-1)、bidirectional-brazed-odf(fd-2)、unidirectional-sae-flare(fd-3)、unidirectional-brazed-odf(fd-4)、replaceable-core-filter-drier(fd-5)

要做的是：**当两段 URL 命中的 subCategory 下「已发布产品恰好 1 个」时，把该页按「单产品详情态」渲染并直出 Product + FAQPage JSON-LD，行为与阀门三段详情页对齐；URL、sitemap、列表浏览体验全部不变。**

## 核心判定（在 src/pages/Products.tsx）
新增一个统一的「详情产品」派生值，建议形态（以你读到的最新代码为准，不要照搬旧行号）：
```ts
// 既有：三段详情产品
const thirdDetailProduct =
  currentThirdCategory && !currentThirdCategory.isOverview
    ? filteredProducts.find((p) => p.thirdCategoryId === activeThirdCategory) ?? null
    : null

// 新增：两段 URL 且该子类「恰好 1 个已发布产品」→ 单产品详情态
const isSingleProductSub =
  !activeThirdCategory &&
  !!currentSubCategory &&
  !isSubCategoryOverview &&
  filteredProducts.length === 1

const detailProduct = thirdDetailProduct ?? (isSingleProductSub ? filteredProducts[0] : null)
```
要点：
- 必须同时满足：无 thirdCategorySlug、命中真实 subCategory、该 subCategory 不是 overview（排除 `/products/filter-driers` 这类分类 landing）、`filteredProducts`（已过滤 isProductPublished）长度恰为 1。
- category 总览（activeSubCategory==='all'）、多产品子类、overview 页一律**不**进入此态，保持现有列表/landing 行为。

## 需要让 detailProduct 驱动的地方（原来是只看 currentThirdCategory）
把以下「产品级」输出的条件由 `currentThirdCategory && !isOverview` 扩展为 `!!detailProduct`，产品对象统一改用 `detailProduct`：
1. **SEO**：seoTitle / seoDescription / seoUrl / keywords / `ogType='product'`。单产品态 canonical(seoUrl) 仍保持当前两段 URL（`/products/{category}/{sub}`），**不要改 URL**。
2. **面包屑 JSON-LD**：单产品态在 subCategory 项之后追加该产品项（name=产品名，url=该两段 URL）。
3. **productDetailSchema（Product）**：单产品态用 detailProduct 产出，与阀门详情字段一致。
4. **faqPageSchema（FAQPage）**：
   - 继续调用 `getProductFAQs(detailProduct.categoryId, detailProduct.subCategoryId, detailProduct.faqSelection, detailProduct.faq)`（第 4 参 detailProduct.faq，签名已存在）。
   - 这些产品（ct-*/im-1/im-2/fd-*）的专属 FAQ 已由 product-faq-seed 注入到 `product.faq`，每产品 3 条；本轮上一改动后 getProductFAQs 只返回型号专属、不再追加通用 3 条。直接复用即可。
5. **页面可见标题区**：单产品态不要再显示「1 product available / subCategory 名」当主标题，主标题/简介按产品详情展示（参照三段详情态：产品 name、shortDesc/description）。列表主体本来在 `filteredProducts.length===1` 时就只渲染这一张 ProductCard，保持不变；用户点 ProductCard 的 View Detail 仍弹 ProductModal 看 FAQ——与阀门详情页完全一致，不要新造 FAQ 展示组件。
6. **noindex 逻辑**：单产品态按「已发布产品详情」处理（可索引），不要被误判成列表/未发布而加 noindex。
7. schemas 数组、Helmet 注入等随之包含 detailProduct 的 Product + FAQPage + 含产品项的面包屑。

## 不需要改 / 不要做
- **不改任何 URL、路由参数结构、分类树数据（products.ts 的层级/字段）、sitemap 枚举逻辑**；不新增 thirdCategoryId，不改产品挂载。
- relatedProducts 区块保持仅三段详情显示即可，本次不强加到单产品子类。
- 不动 FAQ 数据、不动 getProductFAQs 的现有返回规则、不动 ProductModal。
- 不要 push / 部署；本地构建自测通过后停下汇报。

## 预渲染（关键，务必落实到静态 HTML）
本项目阀门三段页是预渲染出含 JSON-LD 的静态 HTML 的。请确认同一预渲染机制会对上面 11 个两段 URL 同样执行 React 渲染（它们已在 sitemap 枚举内）；若预渲染有独立的路由白名单/抓取逻辑，确保这 11 个两段 URL 被覆盖。最终以 **dist 产物里这 11 个 HTML 文件静态含 FAQPage/Product JSON-LD** 为准（不是只在客户端运行后才有）。
